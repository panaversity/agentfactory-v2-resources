# F7. OpenCode version 2

*Sign in.* In `opencode.jsonc`, under `mcp.servers`, remove `"oauth": false` and the `headers` from Chapter 17:

```jsonc
"apts": { "type": "remote", "url": "http://127.0.0.1:8717/mcp", "protocol": "2026-07-28" }
```

Sign-in is on by default for remote servers. Run `opencode mcp auth apts`, or type `/mcps` in OpenCode and authorize. `opencode mcp logout apts` signs out.

*Registration.* OpenCode uses a configured `client_id` first, then a Client ID Metadata Document if the server supports one and you have not set `redirect_uri`. Otherwise it falls back to the older route, which Brightline's sign-in server does not offer. The lab pre-registers OpenCode (Task 15): make a client with `npm run client:add -- --client-id brightline-opencode --name "OpenCode (lab)" --redirect http://127.0.0.1/callback`, then the entry reads `"apts": { "type": "remote", "url": "http://127.0.0.1:8717/mcp", "protocol": "2026-07-28", "oauth": { "client_id": "brightline-opencode", "scope": "ap:read ap:vendors.read", "redirect_uri": "http://127.0.0.1:8792/callback" } }`. OpenCode's page names loopback return addresses with the path `/callback`. Setting `redirect_uri` fixes the port OpenCode listens on, 8792, and turns the document route off. The client's registered address, `http://127.0.0.1/callback`, names no port, and a loopback return address may use any port (F4).

*Scopes.* `"oauth": { "scope": "ap:read ap:vendors.read" }` to ask for more up front.
