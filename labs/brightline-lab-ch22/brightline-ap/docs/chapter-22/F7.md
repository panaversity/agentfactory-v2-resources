# F7. OpenAI and Omnara, for the ports

**OpenAI (Task 19).** You make three things yourself. First, an OpenAI API account with credits. Second, a project with a monthly spend limit of $5 and Enforce a hard limit turned on (Project settings, Limits). Third, a project key in `.secrets/openai.env`, with the permissions `api.agents.read`, `api.agents.write` and `api.responses.write`. The Agents API is reached through the SDK's `client.beta.agents`, with the `OpenAI-Beta: agents=v1` header. Sessions take an `agent` (model, instructions, tools), an `environment` (`{"type": "none"}` runs with no sandbox), `input`, and a budget, `spend_control`, in whole US cents. MCP tools are `type: "mcp"` with `server_label`, `transport: {type: "http", server_url}`, `allowed_tools`, and the session names its vaults in `vault_ids`. Set `required: true` on the connector's tool entry: a connector is optional by default, so without it a failed sign-in gives an answer with no connector call instead of an error. A hosted sandbox may reach any host by default, so set its `network.access` to `disabled`, or to `restricted` with a list of hosts, as 23.7 teaches. Vault credentials apply only when `connection_origin` is `service`, the default. Its vaults take `mcp_oauth` with a refresh block, and deleting a credential does not revoke the provider's token. **Loading a plugin:** a plugin root holds `.codex-plugin/plugin.json`, naming `skills` and `mcpServers` with paths that start with `./`. On a hosted sandbox, upload it as a ZIP in `environment.plugins`: one ZIP for each plugin, with the plugin's folder inside it, and a name and description that match the manifest. On a self-hosted one, list its folder in `environment.capability_directories`. A session does not reload a changed plugin. The documents do not say how a refused refresh is signaled. Task 19 tests whether Chapter 16's plugin loads with only that manifest added.

**Omnara (Task 20).** Needs Docker with Compose. Clone `https://github.com/omnara-ai/omnara`, check out the release pinned in `ports/omnara/README.md`, `cluster-v0.2.17`, and run `OMNARA_RELEASE=v0.2.17 GATEWAY_HOST_PORT=127.0.0.1:8000 REDIS_HOST_PORT=127.0.0.1:6379 POSTGRES_HOST_PORT=127.0.0.1:55432 docker compose -f compose.yaml --profile app up -d`. The release variable makes the images match the release. The three port variables keep the ports on this computer, because Docker otherwise opens a published port on every network address. Open `http://localhost:8000`. Sign up there. The verification link is printed in `docker compose logs api`. Add a model provider (a local model through Ollama, or a hosted one with your own key) and a model, and share both with your project. Then make an agent profile, and add the connector as an HTTP MCP server. Its tools ask by default, so set the four read tools to allow, or the question stops and waits for you. *Security:* the pinned release says its local defaults are intentionally insecure. Run it only on your own computer, never on a network address, and stop it after the task with `docker compose -f compose.yaml --profile app down`: without the profile, `down` stops only the services that have none.
