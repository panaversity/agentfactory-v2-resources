# 21.5 Who remembers the conversation?

**In everyday life.** A family doctor's practice brings in a fill-in doctor for one day. The fill-in doctor has never met the patient and will never see the file again after today. Everything the fill-in doctor needs is in the folder the clinic hands over: every note, every test, in order. Each note a doctor wrote is signed. If the clinic rewrites a signed note, the signature no longer matches, and the fill-in doctor rejects the folder. In this concept, the fill-in doctor is the model, and the folder is the **conversation array**.

**What you will learn.** Why the model remembers nothing between calls, so your program keeps every message and sends all of them each time, unchanged.

**Why it matters.** Owning the whole history means you can print, test and replay exactly what the model saw. Editing it breaks the next call.

**Where this fits.** This is step 2, keep. The model remembers nothing from one call to the next, so your program keeps the whole conversation and sends all of it every time.

The API's documentation says the second call is rejected with an error, because the thinking that went with that tool call was changed. Task 5 lets you see it.

### What does a stateless API mean for the conversation?

The first API is **stateless**: it keeps nothing between calls. Each request must carry the whole history, and the model reads only what that request holds. So the conversation lives in your program, as a **conversation array**, a list of entries in order. Each entry has a role (the person, or the model) and content. The loop adds two entries on each turn that uses a tool: the model's content, then your results. On the last turn it adds only one, the model's answer. Your tool results go in an entry with the person's role, `user`, because the first API has no role of its own for tool results.

Three rules follow:

- **Everything the model produced goes back unchanged.** That includes text, tool calls and **thinking blocks**: the model's reasoning before it answers, which the first API returns as content blocks with a signature. With tool use, the thinking that came with a tool call is sent back with that call, complete and unmodified. Rebuild the entry or edit a block, and the documentation says the next request is rejected with a 400 error. (The API does allow one thing: leaving out the thinking of a question that is already answered. The model then loses that reasoning, and this chapter's loop never does it.)
- **Keep the same thinking setting for the whole loop.** The thinking setting says how the model thinks. With adaptive thinking, which the lab uses, the model decides for each request whether to reason and how much. Set it once, and leave it alone from a question's first call to its final answer. If your code changes it in the middle of a tool-use loop, the API sends no error. It silently turns thinking off for that request.
- **You may add, but do not rewrite the past.** You can add a new question at the end. Changing what the model said earlier makes the history untrue, and some of it, like thinking, the API checks. That check reaches past the thinking block itself. If the instructions, the tools or an earlier entry changed after the model wrote a thinking block, the lab's model may reject the request with a 400. So build the instructions and the tools once for each conversation, and put anything new in a new entry at the end.

### Why is a stateless API good news?

A stateless API means the whole conversation is in your hands, on your computer, in a variable you can print. You can log it, test it, replay it and see exactly what the model saw. Your tests in this lab do just that: they replay recorded responses and check, entry by entry, what the loop sent. Nothing is hidden on a server. 21.7 shows what changes when it is.

### What does sending the whole history cost?

Sending the whole history every time means every turn pays again for everything before it, in tokens and in time. A loop of six turns sends the instructions and tools six times. 21.12 shows how caching makes the repeated part cheap.
