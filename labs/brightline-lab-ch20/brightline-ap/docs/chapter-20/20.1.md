# 21.1 What is an agent, in code?

**In everyday life.** The advisor from Start here slides a note under her door. You decide whether to fetch what it asks for, and you may say no. Either way, she writes nothing more until your reply comes back. In this concept, the advisor is the model, each note is a tool call, and you outside the door are your code.

**What you will learn.** What an agent looks like inside a program: the five steps it repeats, and the three decisions only your program makes.

**Why it matters.** Every action an agent takes passes through code you control and can test. That is what makes an agent safe to build.

**Where this fits.** Start here told Ana's question in plain words. This concept tells the same story the way your program sees it: as requests and responses, and five steps that repeat.

**One request, start to finish.** Ana asks: "Which invoices are due this week?" Here is everything that happens, under the names of the loop's steps:

- **Call.** Your code sends the first request. It holds the instructions (what the worker is for), the conversation so far (just Ana's question) and the four tools, each with its name, a description and the shape of its inputs.
- **Keep, then check.** The model answers with a request, not an answer. It says, in effect: "Please run `list_open_invoices` with `due_on_or_before` set to Sunday's date." This is a tool call, and it carries a **call id**, a unique label for this one request. Your code keeps it, then checks why the model stopped: it wants a tool.
- **Run.** Your code runs the tool. It calls the connector (Start here), over MCP, the same way any AI app calls a connector, and gets back ten invoices.
- **Return.** Your code adds the result to the conversation. The model's request is already there, unchanged. After it goes the **tool result**, your answer to the call, marked with the same call id.
- **Call again.** Your code sends the second request, with the whole conversation, now three entries long: the question, the model's request and the result.
- **Keep, then check: finished.** The model answers in words. It names ten invoices, $24,927.63 in all, nine of them already late. This time it stopped because it was finished. Your code sees that and ends the loop.

Two calls to the model, one call to a tool.

### What are the loop's five steps?

A model's API (Start here) has an **endpoint**, one web address that takes a request and returns a response (Chapter 14 taught the shapes: JSON in, JSON out). An agent, in code, is a loop around that endpoint:

1. Call the model with the instructions, the whole conversation and the tools.
2. Keep what the model sent back by adding it to the conversation.
3. Check why it stopped. If it did not ask for a tool, the loop ends.
4. Run each tool it asked for.
5. Return each result, added to the conversation, then go back to step 1.

*Figure 21.4. The loop in five steps. Every agent you have used runs some version of it.*

Three things in this loop belong to your code, and only your code:

| Your code decides | Why the model cannot |
| --- | --- |
| **Whether each tool runs at all** | The model has no hands. It can only ask. A request your code ignores never happens |
| **What the conversation contains** | The model remembers nothing between calls: the API is **stateless** (21.5). It reads only what you send |
| **When the loop stops** | The model's "I'm finished" is one reason to stop. Your limits are others (21.8) |

This is the whole reason an agent can be made safe. Every effect on the world passes through code you wrote, can read and can test.

**At work.** In Lab 21, Task 3, your coding agent shows you the first API's loop file, in TypeScript and in Python. Before anything runs, you find the five steps in the code (each has a comment, Step 1 to Step 5) and predict which line ends the loop. Then the agent runs Ana's question and prints every request and response, and you match each one to a step.

**The operating rule:** the model only asks. Read every tool call as a request your code may refuse, and keep every effect in code you can read.
