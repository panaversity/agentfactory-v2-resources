# Key: the real scheduled task

There is no single right setting, because products differ. Full credit needs every row filled, from the AI vendor's help page, with its date, and these four choices:

- **Identity.** On a feature that runs under a team or service identity, use it for work the team relies on. If it can only run as you, say so, and say what happens when you are away.
- **Reach.** Only the files the spec names. No write access to the shared AP folder. Its notes folder is the only place it writes.
- **Approvals.** Choose a mode that stops before any act outside its notes folder. Do not choose a mode that skips every check.
- **Deadline check.** A named person or a separate check, at a set time, outside the run. Test it within the lab: set a temporary check a few minutes ahead, expect a test note with a unique file name, withhold that note, and confirm the check notices it is missing.
- **Thanksgiving.** The schedule fires anyway. Say who reads the note that day, or pause it for the week and say who does the review.

**The port.** The spec's rules should not change. Only settings should. The table must name at least the identity difference (on OpenAI a team task runs under the team's service account, on Anthropic a Claude Code routine acts as you) and the approval difference, as Concept 9.8 describes. The stop test must pass on the second AI vendor too: if it does not, the spec relied on one product's behavior, and the spec needs fixing, not the product.
