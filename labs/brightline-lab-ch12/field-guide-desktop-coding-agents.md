# Desktop coding agents: current practice

Exact click paths, shortcuts, file locations and plan limits for Claude Code in the Claude desktop app, Codex in the ChatGPT desktop app, and OpenCode Desktop. Chapter 12 teaches the principles and the differences that change a decision. This guide holds the steps, and it is checked every month. Several features here are in beta or still rolling out, so what you see can differ.

| | Anthropic | OpenAI | Open source |
| --- | --- | --- | --- |
| Where it lives | The Code tab in the Claude desktop app | The Codex view in the ChatGPT desktop app | OpenCode Desktop (beta), in front of a local server |
| Rules file | `CLAUDE.md`, importing `@AGENTS.md` | `AGENTS.md` | `AGENTS.md` |
| Enforced settings | `.claude/settings.json` permission rules | `config.toml` sandbox and approval policy | `opencode.jsonc` permission rules, no sandbox |
| Draft a rules file | `/init` drafts `CLAUDE.md` | `/init` drafts `AGENTS.md` | Ask the **build** agent to draft `AGENTS.md` |
| Review the changes | **Changes** card, `/code-review` | Review pane, `/review` | Desktop review panel, or `git diff` |
| Skills folder | `.claude/skills/` | `.agents/skills/` | `.opencode/skills/`, also reads the other two |
| Side chat | Cmd+semicolon, Ctrl+semicolon or `/btw`, not saved | `/side`, Cmd+Option+S or Ctrl+Alt+S | `/btw` in the terminal client |
| Seeing the app | Browser pane, iOS Simulator pane (macOS, beta) | Built-in Browser, Computer Use plugin | Desktop browser pane |
| Plan or tier needed | Pro, Max, Team or Enterprise | Any ChatGPT plan, including Free | Free software, you pay the model |
| Status | GA, with Projects, the iOS Simulator and several layout features in beta or rolling out | GA, with composer predictions in beta | Desktop in beta, version 2 current |

## Anthropic

- **Where you open it.** Claude Code is the **Code** tab in the Claude desktop app, on macOS, Windows and Linux (beta). Nothing else to install. Before the first message you pick an environment (**Local**, **Cloud**, **SSH**, or **WSL** on Windows), a folder with **Open folder…**, a permission mode and a model. A Cloud session keeps going after you close the app. **+ New** starts another session, and a **Worktree** toggle gives it its own git worktree in `.claude/worktrees/`. Source: [Use Claude Code Desktop](https://code.claude.com/docs/en/desktop), [Claude Code Desktop quickstart](https://code.claude.com/docs/en/desktop-quickstart).
- **Permission modes.** **Manual** asks before edits and commands. **Accept edits** edits files and runs common file commands inside the folder without asking, including `mkdir`, `mv`, `cp` and `rm`. **Plan** proposes a plan and edits nothing. **Auto** lets a background check review each action and block risky ones. **Bypass permissions** is for sandboxed containers or virtual machines only. New sessions often start in Auto: on recent versions in the terminal and editor, and since August 2026 on Pro, Max and Team plans. Check the selector before the first message. The app remembers the mode per folder, except Plan. Source: [Use Claude Code Desktop](https://code.claude.com/docs/en/desktop), [Permission modes](https://code.claude.com/docs/en/permission-modes), [What's new, week 32, 2026](https://code.claude.com/docs/en/whats-new/2026-w32).
- **Permission rules and settings.** Rules live in settings files: `~/.claude/settings.json` (you, every project), `.claude/settings.json` (the project, committed for the team) and `.claude/settings.local.json` (you, this project, kept out of git). Organization settings sit above all three. The order is managed, then command line, then local, then project, then user. Lists such as `permissions.allow` are merged across files. Each rule names a tool and a pattern, such as `"Bash(npm test)"` in `allow` or `"Edit(/data/**)"` in `deny`. Rules are checked deny first, then ask, then allow, so an allow rule can never override a deny rule. A committed file's allow rules wait until you trust the folder, while its deny rules apply at once. Edit and Read deny rules also cover file commands Claude Code recognizes in the shell, such as `sed`, `tee` and `>`, but not a script that opens the file itself. The desktop app reads these same files. Source: [Settings files and precedence](https://code.claude.com/docs/en/settings), [Configure permissions](https://code.claude.com/docs/en/permissions).
- **Instruction files.** `CLAUDE.md` holds your written rules, at four levels: your organization's managed file, `~/.claude/CLAUDE.md` for you in every project, `./CLAUDE.md` or `./.claude/CLAUDE.md` for the project, and `./CLAUDE.local.md` for you in this project only. Files in the folders above where you start load at launch, and those in subfolders load when Claude works there. They are joined, not replaced, from the top folder down. A line such as `@AGENTS.md` imports another file, with paths relative to the file that imports it, up to four levels deep. Claude Code reads `AGENTS.md` only when there is no `CLAUDE.md` or `CLAUDE.local.md`, so the shared-contract pattern is a `CLAUDE.md` that holds `@AGENTS.md`. `.claude/rules/` can hold extra rule files, some limited to certain paths. `/init` drafts a `CLAUDE.md`. Source: [How Claude remembers your project](https://code.claude.com/docs/en/memory).
- **Commands, skills, subagents and memory.** A skill is a folder with a `SKILL.md` file, in `.claude/skills/<name>/` for the project or `~/.claude/skills/<name>/` for you. Typing `/<name>` runs it, and `$ARGUMENTS` in the file stands for what you type after the name. Claude can also load a skill on its own when it fits, unless the file says `disable-model-invocation: true`. Custom commands have been merged into skills, and an old `.claude/commands/<name>.md` file still works. A subagent is a file in `.claude/agents/` or `~/.claude/agents/` with a name, a description, the tools it may use and its model. It runs in its own context. Explore, Plan and general-purpose are built in. Auto memory is the notes Claude writes for itself, kept per repository in `~/.claude/projects/<project>/memory/`. The first 200 lines or 25 KB load into every session, and `/memory` turns it on or off. Source: [Skills](https://code.claude.com/docs/en/skills), [Subagents](https://code.claude.com/docs/en/sub-agents), [How Claude remembers your project](https://code.claude.com/docs/en/memory).
- **Watching the session.** A session rail beside the chat holds cards for the environment, context, connectors, outputs, changes, servers and background tasks. The **Context** card shows how full the context is and what fills it. In local and SSH sessions, a box at the end of the conversation shows Claude's plan while it works. Right-click a card's header to choose which cards show. Source: [Use Claude Code Desktop](https://code.claude.com/docs/en/desktop), [Claude apps changelog](https://claude.com/docs/cowork/changelog).
- **Many sessions.** Option-click (Alt-click on Windows) a session in the sidebar, or right-click it and choose **Open in**, then **Split view**, to see two at once. **Group and sort** groups the sidebar, and your own groups are called sections. A side chat (Cmd+semicolon on macOS, Ctrl+semicolon on Windows, or `/btw`) can read the main session so far and adds nothing back to it. The app does not save side chats after you close it. In local and SSH sessions, Claude can start a task in a nested session, which appears under the original in the sidebar and reports back to it. Sessions can message each other, but a message is only the text one Claude writes to another, never its conversation history. Source: [Use Claude Code Desktop](https://code.claude.com/docs/en/desktop), [Claude apps changelog](https://claude.com/docs/cowork/changelog), [Cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging).
- **Seeing the app.** The **Browser** pane (Cmd+Shift+B, or Ctrl+Shift+B on Windows) lets Claude start a dev server, open your app and check its own changes. Dev servers are set in `.claude/launch.json`, and **Auto-verify changes** is on by default. It does not open your app in SSH sessions. On macOS, the **iOS Simulator** pane, in public beta on Pro, Max, Team and Enterprise, lets Claude build a phone app, tap through it and read the screen. It needs Xcode 26 and works in local sessions only. Claude opens it when it runs your app. Source: [Use Claude Code Desktop](https://code.claude.com/docs/en/desktop), [iOS Simulator pane](https://code.claude.com/docs/en/desktop-ios-simulator).
- **Suggested tasks and saved environments.** When Claude notices something worth fixing outside your task, in local and SSH sessions it shows a card with **Start**, which runs it in another session listed under the current one, and **Do it here**. To save a setup, open the environment selector, choose **New environment**, pick **Local**, **SSH** or **Cloud**, and select **Create environment** (or **Add environment** on the Cloud tab). A saved local or SSH environment holds its folders, with a worktree and branch setting for each. Source: [Use Claude Code Desktop](https://code.claude.com/docs/en/desktop), [Claude apps changelog](https://claude.com/docs/cowork/changelog).
- **Projects.** In public beta on Pro and Max, rolling out gradually, and not yet on Team or Enterprise. A project is one long-running coordinator session that starts threads, usually in the cloud, each with its own context. The coordinator sees what threads report, not every step. Cloud threads share a `MEMORY.md` file and load the repository's `CLAUDE.md` and `.claude/rules/`, but not its skills, or the permission rules and hooks in `.claude/settings.json`. Subagents, by contrast, run inside one session. Source: [Projects in Claude Code](https://code.claude.com/docs/en/claude-projects).
- **Keeping it lean.** `/doctor` runs a checkup of your setup. `/doctor prompt-audit` reviews your `CLAUDE.md`, `AGENTS.md`, rules, skills, commands, subagents and output styles for outdated or conflicting instructions, and changes nothing until you ask. `/skill-doctor` shows what each skill costs in context and how often it is used. `/output-style` picks how answers are written, from built-in styles or your own files in `.claude/output-styles/`. Source: [Commands](https://code.claude.com/docs/en/commands), [How Claude remembers your project](https://code.claude.com/docs/en/memory), [Output styles](https://code.claude.com/docs/en/output-styles).
- **Advisor.** `/advisor opus` lets a Sonnet or Haiku session consult Opus at key moments, and Claude decides when. It is experimental and not available through Amazon Bedrock, Google Cloud or Microsoft Foundry. On subscription plans, its use counts toward your usage limits. Source: [Advisor](https://code.claude.com/docs/en/advisor).
- **Mods.** A mod is a plugin that changes how Claude Code looks and behaves: a pane, a band above the prompt, a new command, or a check on tool calls. A mod can also send one request to a different model, for example a cheaper one for a simple step. Mods need Claude Code 2.1.286 or later in the desktop app. Type `/status` in a local session to see the version. To make one, describe it in a session, or run `/plugin-authoring`. Claude writes it under `~/.claude/dev-mods/`, followed by the session's ID. That is a protected folder, so in Manual and Accept edits modes Claude Code asks before each file. When the first file is saved, it asks whether to enable hot reloading: **Enable for this session** loads the mod when the turn ends, and **Not now** loads nothing. The mod loads only in that session. To keep it, copy its folder somewhere of your own and load it with `claude --plugin-dir`. Before you install anyone else's mod, run `claude plugin validate` on its folder and read the `hooks:` and `calls:` lines. `/plugin` lists and turns off installed mods, and `--safe-mode` starts a session without them. Anthropic says mods are not sandboxed: a mod can read and write your files, read your secrets, see every prompt, and approve a tool call before you are asked. Mods do not load in WSL sessions, and nothing a mod draws appears in `claude -p` runs or cloud sessions. Source: [Mods](https://code.claude.com/docs/en/plugins/mods/overview), [Create a mod](https://code.claude.com/docs/en/plugins/mods/create), [Mod events](https://code.claude.com/docs/en/plugins/mods/events).
- **Artifacts and Claude Design.** From the Code tab Claude can publish an artifact, a live page on claude.ai, and `/artifacts` lists yours. `/design` drafts designs on a canvas, when the Design template is on. The standalone Claude Design site closes on December 14, 2026, and new designs and slide decks are now artifacts in Claude. Source: [Artifacts](https://code.claude.com/docs/en/artifacts), [Migrate from standalone Claude Design to Claude](https://support.claude.com/en/articles/17440474-migrate-from-standalone-claude-design-to-claude).
- **Model and effort.** The model picker sits under the prompt box, with **Effort** inside it. On paid plans the default is Opus 5.5. Sonnet 5.5 and Haiku 5.5 are the other choices, and Fable 5.1 where it is available to you. Effort runs from low to max, and the default on the 5.5 models is medium. Source: [Use Claude Code Desktop](https://code.claude.com/docs/en/desktop), [Model configuration](https://code.claude.com/docs/en/model-config).
- **Context and undo.** `/context` shows what fills the context, `/compact` summarizes on demand, and `/btw` asks a side question. `/rewind` takes back files Claude edited with its own tools. A file that only shell commands changed is not tracked. Source: [Use Claude Code Desktop](https://code.claude.com/docs/en/desktop), [Checkpointing](https://code.claude.com/docs/en/checkpointing).
- **Reviewing changes.** A **Changes** card shows the diff. You can comment on lines and send the comments back. `/code-review`, or its alias `/review`, reviews your branch and uncommitted changes in a subagent and reports findings, which the desktop app shows as a list. Add `--fix` to have Claude apply them. **Create PR** needs the GitHub command-line tool, `gh`. Source: [Use Claude Code Desktop](https://code.claude.com/docs/en/desktop), [Review locally with /code-review](https://code.claude.com/docs/en/code-review-local).
- **Outside the app.** The command-line version is a separate install. `claude -p "<task>"` runs one task headless. `--output-format` returns `text`, `json` or `stream-json`, which streams each event as a line of JSON. With `--output-format json` and `--json-schema`, the answer arrives in a `structured_output` field that matches your schema. A headless run starts in Manual mode and denies anything that needs approval, so list what it may do with `--allowedTools`. Anthropic recommends `--bare` for scripts. It skips loading `CLAUDE.md`, skills, hooks, plugins, MCP servers and auto memory, so a run behaves the same on every machine, and it needs an API key instead of your subscription login. In the desktop app, `/resume` picks up a session started in the terminal. Source: [Advanced setup (installing the command-line version)](https://code.claude.com/docs/en/setup), [Run Claude Code programmatically](https://code.claude.com/docs/en/headless), [What's new, week 35, 2026](https://code.claude.com/docs/en/whats-new/2026-w35).
- **Status and price.** Claude Code needs a Pro, Max, Team or Enterprise plan. On Pro and Max it shares usage limits with Claude chat. Source: [Claude Code Desktop quickstart](https://code.claude.com/docs/en/desktop-quickstart), [Use Claude Code with your Pro or Max plan](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan).

## OpenAI

- **Where you open it.** Since July 9, 2026, Codex is a view inside the **ChatGPT desktop app** for macOS and Windows, beside Chat and Work. A Linux version is in preview. Source: [What's new in Codex](https://learn.chatgpt.com/codex/whats-new), [The ChatGPT desktop app](https://learn.chatgpt.com/docs/app).
- **Folder and machine.** You open a folder or a project. **Work in** chooses **This computer** or **Cloud**, and a git project can also run in **Worktree** mode. A cloud task needs a published environment, which Codex helps you set up from your repositories. It cannot reach your computer's files, running programs or VPN, and you can follow it on the web or on your phone. Source: [The ChatGPT desktop app](https://learn.chatgpt.com/docs/app), [Codex modes: Local, Worktree and Cloud](https://learn.chatgpt.com/codex/environments/modes).
- **Permissions.** **Ask for approval** (OpenAI's recommendation), **Approve for me**, **Full access** or **Custom**, set in `config.toml`. Behind them sit a sandbox (read-only, workspace-write or full access) and an approval policy. `/plan` asks for a plan first. Source: [Permission modes](https://learn.chatgpt.com/codex/permission-modes), [Sandboxing](https://learn.chatgpt.com/codex/sandboxing), [Long-running work](https://learn.chatgpt.com/codex/long-running-work).
- **Watching and many chats.** `/goal` sets what done looks like and adds a progress row above the composer. `/status` shows context usage. The **Projects** view groups chats, and you can pin a project. A chat can pop out into its own window. `/side`, or Cmd+Option+S (Ctrl+Alt+S on Windows), opens a side chat without interrupting the main one. Source: [Long-running work](https://learn.chatgpt.com/codex/long-running-work), [Slash commands](https://learn.chatgpt.com/codex/reference/slash-commands), [Projects](https://learn.chatgpt.com/codex/projects), [Settings](https://learn.chatgpt.com/codex/reference/settings), [App commands and shortcuts](https://learn.chatgpt.com/docs/app/commands).
- **Subagents.** Ask for subagents or parallel work in plain words, and the app shows each subagent's thread and the summary it returns. You steer a running subagent by asking Codex. A subagent takes the parent's model and effort unless its own settings say otherwise, and always the parent's sandbox. Custom agents are TOML files in `.codex/agents/`. **Ultra**, on supported models, splits a complex task across subagents that work in parallel. Subagent work uses more tokens than one agent. Worktrees and **Hand off** keep parallel chats apart. Source: [Subagents](https://learn.chatgpt.com/codex/agent-configuration/subagents), [Codex models](https://learn.chatgpt.com/codex/models), [Git worktrees](https://learn.chatgpt.com/codex/environments/git-worktrees).
- **Skills and extensions.** A skill is a folder with a `SKILL.md` file in `.agents/skills/`, and you pick one with `@` in the app. Custom prompts are deprecated in favor of skills. Plugins bundle skills, MCP servers and hooks, and hooks can run before and after tool calls. Settings, then **Appearance**, changes the theme and fonts. We found no advisor, no audit of your instruction files, and nothing like mods that adds panels to the app in OpenAI's documentation. Source: [Build skills](https://learn.chatgpt.com/codex/build-skills), [Custom prompts](https://learn.chatgpt.com/codex/custom-prompts), [Plugins](https://learn.chatgpt.com/codex/plugins), [Hooks](https://learn.chatgpt.com/codex/hooks), [Settings](https://learn.chatgpt.com/codex/reference/settings).
- **Seeing the app.** The app's built-in **Browser** opens a local web app in a tab. Codex can take screenshots and check its work there, and **Annotate** lets you mark an element for it to fix. The browser is not in the command-line tool. There is no iOS simulator pane. On macOS and Windows, the Computer Use plugin can operate other apps, including a simulator. Source: [Browser](https://learn.chatgpt.com/codex/browser), [Computer Use](https://learn.chatgpt.com/codex/computer-use).
- **Suggestions, recaps and environments.** **Composer predictions**, in beta on personal Pro plans, suggest a next prompt in the same chat, and Tab accepts it. We found no option in OpenAI's documentation to start a suggestion as a new chat, and no end-of-turn recap card. A goal pauses when it needs your decision. A cloud environment is a setup you publish once and pick with **Work in**, then **Cloud**. A local environment runs setup scripts each time Codex creates a worktree. A project can hold several folders, and SSH machines are added under Settings, then **Connections**. Source: [Composer predictions](https://learn.chatgpt.com/codex/features/composer-predictions), [Long-running work](https://learn.chatgpt.com/codex/long-running-work), [Cloud environments](https://learn.chatgpt.com/codex/environments/cloud-environments), [Local environments](https://learn.chatgpt.com/codex/environments/local-environment), [Projects](https://learn.chatgpt.com/codex/projects), [Remote connections](https://learn.chatgpt.com/codex/remote-connections).
- **Documents and models.** The app previews documents, presentations, spreadsheets and PDFs that Codex makes, beside the chat. We found no automatic routing to a cheaper model in OpenAI's documentation. You choose the model, and you can give subagents their own default model. Source: [Work with files](https://learn.chatgpt.com/codex/artifacts-viewer), [Model selection](https://learn.chatgpt.com/codex/model-selection), [Subagents](https://learn.chatgpt.com/codex/agent-configuration/subagents).
- **Model and effort.** GPT-6 Astra is the most capable model, then GPT-6.1 Sol, GPT-6.1 Terra and GPT-6 Luna. Reasoning effort runs Light, Medium, High and Extra High, and on supported models also **Max**, which gives one hard task more time, and **Ultra**, which splits a task across parallel subagents. GPT-6 Luna goes up to Max but not Ultra. Source: [Codex models](https://learn.chatgpt.com/codex/models).
- **Rules files.** Codex reads `AGENTS.md`: a personal one in `~/.codex`, then one in each folder from the repository's root down to where it works, joined root first, up to 32 KiB. `/init` in the composer generates an `AGENTS.md` scaffold. Settings live in `config.toml`. Source: [AGENTS.md](https://learn.chatgpt.com/codex/agent-configuration/agents-md), [Config basics](https://learn.chatgpt.com/codex/config-file/config-basic), [Slash commands in the app](https://learn.chatgpt.com/codex/reference/slash-commands).
- **Reviewing changes.** The review pane shows unstaged, staged and committed changes, the branch and the last turn, and you can stage or revert a file or one part of it. `/review` reviews either your uncommitted changes or your branch against its base, and reports findings by priority without changing your files. Source: [Code review](https://learn.chatgpt.com/codex/code-review).
- **Outside the app.** The Codex command-line tool is open source. `codex exec` runs one task headless, read-only by default, and can return JSON that matches a schema. OpenAI offers a GitHub Action for CI. Source: [Codex on GitHub](https://github.com/openai/codex), [Non-interactive mode](https://learn.chatgpt.com/codex/noninteractive).
- **Status and price.** Codex is on every ChatGPT plan, including Free, where it uses GPT-6 Luna. Plus is $20 a month, with five-hour usage limits. Pro is $100, $200 or $500. Source: [Codex pricing](https://learn.chatgpt.com/codex/pricing).

## Open source

- **What changes.** OpenCode is a free coding agent under the MIT license. You install it, pick a model and set its safety rules yourself. There is no vendor sandbox and no vendor cloud. Source: [README](https://github.com/anomalyco/opencode), [Download](https://opencode.ai/download).
- **Where you open it.** **OpenCode Desktop** runs on macOS, Windows and Linux, still labeled beta. In version 2 it talks to a background OpenCode server on your computer, which runs the sessions and tools. Source: [README](https://github.com/anomalyco/opencode), [CLI and server](https://opencode.ai/v2/docs/cli/).
- **Models.** `/connect` adds a provider with your own API key. You can also sign in with a ChatGPT Plus or Pro plan, run a local model, or buy OpenCode Go ($10 a month). We found no way to sign in with a Claude subscription in OpenCode's version 2 documentation, so use an Anthropic API key for Claude models. Source: [Providers, version 2](https://opencode.ai/v2/docs/providers/), [OpenCode Go](https://opencode.ai/go).
- **Agents and permissions.** **build**, the default, edits and runs commands. **plan** explores and plans without editing. Permission rules are an ordered `permissions` list in `opencode.jsonc` (or `opencode.json`) in the project folder. Each rule names an action such as `edit` or `shell`, a resource, and an effect of allow, ask or deny. If no rule matches, OpenCode asks. The default policy allows `external_directory`, files outside the project, so add an ask rule for it. Version 1 used a different form, with `permission` and `bash`, so check which version an example is for. Desktop can override auto-accept per project, under Settings, then Projects. Source: [Agents](https://opencode.ai/v2/docs/agents/), [Permissions](https://opencode.ai/v2/docs/permissions/), [Config](https://opencode.ai/v2/docs/config/), [Changelog](https://opencode.ai/changelog).
- **Watching and many sessions.** In version 2 the to-do tool is off by default. Turn on `experimental.todo`, and Desktop shows the tasks above the composer, though OpenCode says the feature may change. Desktop shows a session's context tokens and cost, and a review panel shows each completed turn's changed files, line counts and diffs (Settings, then Preferences, then Timeline, then Changed files). Desktop has session tabs. In the terminal client, `/btw` asks a side question that is not added to the conversation. You can fork a session from any message. Source: [Config](https://opencode.ai/v2/docs/config/), [Changelog](https://opencode.ai/changelog), [Terminal client](https://opencode.ai/v2/docs/cli/tui/).
- **Subagents and models.** Two built-in subagents, **general** and **explore** (read-only), run in child sessions, and each starts with fresh context, not the parent's conversation. The parent can continue a child by its session ID, and in the terminal client Enter steers the session you are looking at. Custom agents are markdown files in `.opencode/agents/`, and each can have its own model, such as a fast one to explore and a strong one to review. There is no advisor. Source: [Agents](https://opencode.ai/v2/docs/agents/), [Tools](https://opencode.ai/v2/docs/tools/), [Terminal client](https://opencode.ai/v2/docs/cli/tui/).
- **Commands, skills and plugins.** Commands are markdown files in `.opencode/commands/`, with `$ARGUMENTS`. Skills use a `SKILL.md` file in `.opencode/skills/`, and OpenCode also reads `.claude/skills/` and `.agents/skills/`. Plugins can hook into tool calls, and Desktop plugins can add panels, though that API is experimental. OpenCode does not sandbox the agent, so treat a plugin, and a repository's `.opencode/plugins/` folder, as code you are choosing to run. Source: [Commands](https://opencode.ai/v2/docs/commands/), [Skills](https://opencode.ai/v2/docs/skills/), [Plugins](https://opencode.ai/v2/docs/build/plugins/), [Server plugins](https://opencode.ai/v2/docs/build/plugins/server/), [Security policy and advisories](https://github.com/anomalyco/opencode/security).
- **Seeing the app, and environments.** Desktop has a browser pane that the agent controls through its browser tool, with screenshots. Browser actions do not ask for permission one by one. We found no iOS simulator, suggested follow-up tasks or end-of-turn recap in OpenCode's documentation. Desktop can connect to several OpenCode servers, and a new session picks its project and worktree in one dialog. We found no hosted cloud environment and no automatic model router. A plugin can switch a session's model. Source: [Tools](https://opencode.ai/v2/docs/tools/), [Changelog](https://opencode.ai/changelog), [Server plugins](https://opencode.ai/v2/docs/build/plugins/server/).
- **Rules files.** OpenCode reads `AGENTS.md` from the project and your personal folder. Version 2 does not read `CLAUDE.md`. We found no `/init` command in OpenCode's version 2 documentation, so write `AGENTS.md` yourself or ask the **build** agent to draft it. Read the changes in Desktop's review panel, or with `git diff`. Source: [Instructions](https://opencode.ai/v2/docs/instructions/), [Terminal client](https://opencode.ai/v2/docs/cli/tui/), [Changelog](https://opencode.ai/changelog).
- **Context and undo.** OpenCode compacts on its own near the limit. `/undo` and `/redo` roll its changes back and forward, but snapshots are not a backup. They skip some files and cannot undo commits. Source: [Compaction](https://opencode.ai/v2/docs/compaction/), [Snapshots](https://opencode.ai/v2/docs/snapshots/).
- **Security.** OpenCode does not sandbox the agent. Its security policy says permission prompts are not isolation, and recommends Docker or a virtual machine. The default rules allow almost everything, shell commands run with your full user rights, and the local server has no password unless you set one. Three advisories were published in 2026, two of them for a server that could be made to run commands or install packages. Before your first task, set edits and shell commands to ask, keep OpenCode updated, and never expose its server to a network. Source: [Security policy and advisories](https://github.com/anomalyco/opencode/security), [Permissions](https://opencode.ai/v2/docs/permissions/).
- **Status and price.** The software is free. You pay your model provider or OpenCode's plan, unless you run a local model. Source: [README](https://github.com/anomalyco/opencode), [Providers, version 2](https://opencode.ai/v2/docs/providers/).
