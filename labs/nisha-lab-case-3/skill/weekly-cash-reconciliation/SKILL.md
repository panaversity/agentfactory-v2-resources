# Weekly cash reconciliation

The method of Nisha's firm, written by Sana, the firm's reviewer. The firm and the method are made up for teaching. This is not accounting advice.

## When to use this skill

Use it when someone asks you to reconcile a client's cash for a week, to check a reconciliation file, or to say what kind of difference a bank line or ledger line is.

## Steps

1. Match each bank line to a ledger line. A match has the same amount, a date within seven days, and the same reference or invoice number when one is given.
2. List every bank line and every ledger line that has no match.
3. Give each unmatched line exactly one label from `references/labels.md`. Do not invent a label.
4. Work out reconciled cash from the bank side: the bank's closing balance, plus deposits not yet cleared, less checks not yet cashed.
5. Compare reconciled cash with the ledger's closing balance. List each thing that explains the gap, with its amount.

## Rules that are never broken

- **A payment that has cleared the bank with no ledger line is an open item.** It is never a timing item until a document explains it. Never add such a payment back to make the two sides agree.
- **Two bank payments to the same payee for the same invoice number, or for the same amount within seven days, are a suspected duplicate.** Say "suspected". Name the document that would confirm it, such as the supplier's statement.
- **The first line is READY or NOT READY.** Write NOT READY when there is any open item or suspected duplicate. List those items directly under the first line, in plain words, with their amounts. Never leave them only in a note at the end.
- **Say what you could not check**, and which document you would need.

## Output

Write the file in this order.

1. Status: READY or NOT READY
2. Open items and suspected duplicates, if any
3. Reconciled cash, and the period it covers
4. The reconciliation table
5. Notes on timing items
6. What you could not check

## What this skill does not do

This skill is about how to prepare and check the file. It does not decide who may send the file to the client. A named person approves each file, and sending is controlled by where the mailbox is available. If you are asked to send a file that is NOT READY, say that it is not ready and who needs to decide.
