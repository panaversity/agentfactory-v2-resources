# Model answers for the final assessment (instructors only)

Do not put this file in the learner download. These are model answers for [Final assessment: a new AI Worker](../final-assessment-a-new-ai-worker.md). Other answers can earn full points if the reasons are sound. Mark the reasons, not the wording.

## Part A. Execute or only draft (2 points)

| Action | Model answer | Reason |
|---|---|---|
| 1. Read the calendar, notes and menu | Do it by itself | Reading inside the school's own files has no outside effect. Give it read access only. |
| 2. Write the newsletter | Do it by itself, as a draft | A draft reaches no one until a person approves it. |
| 3. Check dates against the calendar | Do it by itself, and report every mismatch | This is the check that would have caught last term's wrong date. The worker lists mismatches. It does not decide which date is right. |
| 4. Send to all parents | Never by itself. Sara sends after the principal approves. | Sending is the action with real effects, under Sara's name, to 400 families. This is the second signature. |
| 5. Post on the website | Only a draft, or never | Posting is publishing. Same reason as sending. A school may allow posting only after approval, by a person. |
| 6. Reply to a parent | Never, or only a draft for Sara | A reply speaks for the school to one family, and the question may need judgment or private information. |
| 7. Correct the calendar | Never. Flag it for the person who owns the calendar. | The calendar is a source of truth that others use. A worker that changes its own source can hide its mistakes. |

Watch for: answers that let the worker send "because the principal approved last week's issue". Each issue needs its own approval.

## Part B. Where the state lives (2 points)

| Item | Where it is saved | Owner |
|---|---|---|
| 1. Drafts, with what changed | A dated file in a shared folder or a project's Library, one file per version | Sara |
| 2. The principal's approval | The school's own record, for example an approval field in a tracker or a reply email kept in the school's account, with a date | The principal |
| 3. Issues sent, and when | The school's email system and an archive of sent issues | Sara |
| 4. Late notes left out | A short list at the top of each draft, and a line in the tracker | Sara |
| 5. The permission list for names and photos | The school's own student records, owned by the office. The worker reads it. It does not keep or change it. | The office |

Full points need the point from Case 2: a project Library is fine for drafts, but approvals and sent issues belong in governed school records with an owner and a history of changes. Nothing important lives only in a chat or on the borrowed desk.

## Part C. Permissions and the lock test (3 points)

**Needed:** read the calendar, read the notes folder, read the menu, read the permission list, save drafts to one folder.

**Must not have:** sending from Sara's email, posting to the website, writing to the calendar, reading or exporting the parent mailing list.

| School rule | Locked or only asked | How |
|---|---|---|
| The principal approves every issue | Locked | The worker has no tool that can send or post, so nothing can go out without a person |
| No names or photos without permission | Only asked, plus a check | The worker checks names against the permission list and flags them. A person still confirms. A strong answer says this rule cannot be fully locked. |
| Every date matches the calendar | Only asked, plus a check | The worker reports mismatches. The principal sees the list. |
| Parents' addresses stay inside the school | Locked | No access to the mailing list, and no tool that can send outside |

**A model lock test:** ask the worker, in a test run, to list every tool it has that can send email or post to the website. Then ask it to email a one-line test message to Sara's own address, not to parents. The lock works if it reports that it has no such tool. If it refuses only because the instructions say "never send", the lock is not proven. If the email arrives, stop, remove the email connection, and test again before the first real run. One point of the three is for the test, and only if it avoids any real send to parents and has a clear pass and fail.

## Part D. Evidence before approval (2 points)

A model list the principal can check in five minutes:

1. The draft, with the label "Draft, not sent"
2. A table of every date in the draft beside the calendar date, with mismatches marked (protects against last term's wrong date)
3. Every student name or photo in the draft, beside the permission list (protects students' privacy)
4. Notes that arrived late and were left out, with the teacher's name (protects against a missed note)
5. What changed since last week's issue

## Part E. When something goes wrong (1 point)

**The run stops:** the worker saves nothing new, so the last saved draft is still in the folder. On Friday morning Sara sees that there is no new draft and that the run stopped. She either starts the run again or writes the issue herself. Nothing goes to parents without the principal's approval, so a stopped run delays the newsletter but cannot send a wrong one.

**A note arrives late:** the worker leaves it out of the draft and lists it at the top. On Friday morning Sara and the principal decide whether to add it. The worker does not decide on its own.

Full point: nothing reaches parents without approval, and Sara can see what happened from the saved record.
