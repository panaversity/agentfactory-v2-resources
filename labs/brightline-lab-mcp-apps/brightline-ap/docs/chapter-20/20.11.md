# 20.11 How does a skill travel with the connector?

**In everyday life.** A franchise sends each new shop the same recipe binder, with a numbered list of pages on the cover. When a shop opens the binder, it checks the page count against the cover, so a missing or swapped page is caught.

**What you will learn.** How a connector shares a skill with any AI app that connects, and how the AI app checks it got exactly what the connector sent. You build it in Lab 20, Task 10.

**Why it matters.** In Chapter 16, the `invoice-triage` skill lived in a plugin each person installed (16.5). 16.7 carried it to three AI tools, one label at a time. Cedar Ridge's people use other AI apps, and some never install plugins. If the skill travels with the connector, the method reaches everyone who connects. The method is the same for every company. Each company's own rules, such as Cedar Ridge's $2,500.00 approval threshold, stay in its settings row (19.11), and the tools read them.

**One request, start to finish.** Luis asks, "Which invoices should I look at first today?"

1. **The AI app asks the connector which skills it has,** with `skills/list`. For each skill it gets the address of its `SKILL.md`, its name and description, and a manifest: every file, with its size and a fingerprint.
2. **The model reads the descriptions** and picks `invoice-triage`. The AI app may ask Luis first.
3. **The AI app reads `skill://invoice-triage/SKILL.md`** with the ordinary `resources/read`, and checks its size and fingerprint against the manifest.
4. **It loads the instructions,** tagged with the connector they came from, and the model follows them, calling `list_open_invoices` as the skill says.

### What is Skills over MCP?

It is the extension `io.modelcontextprotocol/skills`. A skill is the same folder you met in 16.1: a `SKILL.md` with a name and description, and supporting files. The extension adds two requests and reuses one:

- **`skills/list`** returns every skill: its `SKILL.md` address, its header fields, and a complete manifest of its files, each with a SHA-256 fingerprint and size. A fingerprint changes if one letter of the file changes.
- **`skills/get`** returns one skill's entry, when the AI app has only its address.
- **`resources/read`** reads `SKILL.md` and any supporting file, from addresses such as `skill://invoice-triage/references/rules.md`, only when it is needed.

Reading `SKILL.md` does not by itself turn the skill on. The AI app loads it in its own way of loading skills, which checks the content and asks for any approval first.

### What does the AI app check?

While it uses a skill, the AI app keeps the entry it loaded. It reads only files named in that manifest, checks each file's size and fingerprint before use, and compares the `SKILL.md` header with the listed one. Content that fails any check is not used.

### May an AI app keep the list for the next person?

Every list of skills says how long it may be reused, and by whom. A list marked `public` may be kept in a shared cache, one saved copy for many callers, and served to any caller. A list marked `private` may be reused only for the same sign-in. Brightline's triage skill is the same for every company, so `public` is safe for it. A skill built for one company, such as its own approval steps, must be marked `private`, or a shared cache could hand it to another company. The mark is not a lock. The connector still checks every call.

### Is a skill on the server protected from copying?

No. Once the AI app loads it, the person can read it, as with a plugin (16.9). Its numbers still belong in tested code (16.2), and a served skill's scripts run only after the person approves them (20.12). A skill served from the connector is easier to keep up to date, not secret. For a connector you sell, keep the value in the tools the skill calls, behind the plan check (20.15).

**At work.** In Lab 20, Task 10, Claude Code serves `invoice-triage`, with its rules file, from the TypeScript connector, under the name `brightline-invoice-triage`, so it cannot collide with another server's skill of the same name (20.12). Codex does the same in Python.

**The operating rule:** serve a skill with a complete manifest, let the AI app read each file only when it needs it, and keep anything worth paying for in the tools, not in the skill.
