# 20.16 How do today's products do this?

*As of November 26, 2026. Each AI app changes these details often. Check them before you build.*

**In everyday life.** A standard plug fits every socket, but each house puts its sockets and switches in different places. In a new house, you look for the switch once, then use it every day.

**What you will learn.** Where Claude, ChatGPT and an open-source AI app keep the controls for a connector with screens: how to add the connector, what each asks the first time, and how to tell the screen worked. You use these steps in Lab 20, Task 3 in Claude and Task 8 in a second AI app.

**Why it matters.** The screen is built to one standard (20.9), but the way to reach it differs in each AI app. A step done in the wrong place looks like a broken screen.

## How to show your connector's screen in your app

### Claude

1. **Put the connector online.** Claude connects to it from Anthropic's cloud, not from your computer, so its address must be reachable over the public internet, on the standard HTTPS port. An address with another port, such as `https://example.com:8443/mcp`, does not connect. Set the page's `ui.domain` for that address before you add it (see Product reference).
2. **Add it.** Open *Customize > Connectors*, click *+ Add*, then *Add custom connector*. Enter a name and the server's address with its path, such as `https://example.com/mcp`, and click *Continue*.
3. **Choose how people sign in.** Under *Authentication*, choose *Sign in now* or *Sign in when needed* for a connector with sign-in, such as Brightline's. Then click *Add*. On a Team or Enterprise plan, an Owner adds the connector in *Organization settings > Connectors*, and each person then clicks *Connect*.
4. **Turn it on in a chat.** Click the *+* button at the lower left, then *Connectors*, and turn the connector on.
5. **Ask for the tool,** such as "show my open invoices". Before a page first appears, Claude asks: *Allow once*, or *Always allow* for a server you trust.
6. **Check it worked.** The screen draws in the chat. If it does not, open the page's developer tools. In Claude Desktop, choose *Help > Troubleshooting*, click *Enable Developer Mode*, then press `Cmd+Option+I` on a Mac or `Ctrl+Shift+I` on Windows. Your page is the inner of two frames, one inside the other. Claude's page does not say how to do this on the web.

On Claude's free plan, you can add one custom connector.

### ChatGPT

1. **Put the connector online,** at a public HTTPS address with its `/mcp` path.
2. **Add it.** Go to *ChatGPT Plugins*, select the plus button, then *Add custom MCP server*. Enter a name and a description.
3. **Connect.** Under *Connection*, enter the server's address with its `/mcp` path. Set up sign-in, read the risk warning, and select *I understand and want to continue*. Then select *Create as a plugin*, and review the tools ChatGPT found.
4. **Use it.** Install the plugin, start a new conversation, type `@` and select the plugin. Then ask for the tool.
5. **Check it worked.** Test both the screen and the text the model reads.
6. **After you change the page or a tool,** open the connection in *ChatGPT Plugins*, select *Refresh*, and start a new conversation.

Your account's and workspace's policies decide whether you may add a custom MCP server.

### Open source

1. **Add the connector to Goose.** In the desktop app, click the button at the top left to open the sidebar, click *Extensions*, then *Add custom extension*. Enter the details, then click *Add*. In the command-line version, run `goose configure`, choose *Add Extension*, then *Remote Extension (Streamable HTTP)*, or add it for one session with `goose session --with-streamable-http-extension "https://example.com/mcp"`.
2. **Sign in.** Goose's page does not say how it signs in to a connector that needs sign-in, such as Brightline's. Check that before you rely on it.
3. **Check it worked.** Ask for the tool. Goose is among the AI apps the MCP project lists as showing MCP Apps, so the screen should draw. A coding agent that shows no screens, such as OpenCode, gives you the text answer instead (20.9).

To look at a page on your own computer before any AI app, use the MCP project's basic host, in the field guide's F1.

## What changes a step

**Where the connector runs.** It decides which AI apps can reach it:

| The connector runs | Claude | ChatGPT | Goose |
| --- | --- | --- | --- |
| Online, at a public HTTPS address | Yes | Yes | Yes, as a remote extension |
| On your own computer | Only as a local server in Claude Desktop's own settings, not as a custom connector. Claude does not call a page's own tools then | Only through a tunnel, such as Secure MCP Tunnel | Yes, as a command-line extension |

The table comes from each AI app's own page.,,,

**When the AI app asks first.** Claude asks the person before a page first appears. ChatGPT shows its risk warning once, when you add the server.,

## What stays the same

The standard behind the screen is the same in every AI app that implements it: tool visibility (20.5), the sandbox (20.6) and the text answer (20.9). And in every one of them, a press on the screen reaches your connector as a call with the person's token, checked like any other call (20.4).

## Product reference

*For looking things up, not for reading through.*

**The standard.** MCP Apps, `io.modelcontextprotocol/ui`, revision 2026-01-26, stable. Tool visibility, the sandbox rules and the text fallback are the same in every AI app that implements it.

**Claude.** Claude calls MCP Apps interactive connectors. They are available to all users on the web, in Claude Desktop and in the iOS and Android apps. Before a page first appears, Claude asks the person: *Allow once*, or *Always allow* for a server they trust. On Team and Enterprise, owners can turn off the tool calls that show screens, without turning off the connector. Claude serves each page from its own sandbox address. Set the page's `ui.domain`, with the rest of its `_meta.ui` on the content that `resources/read` returns, to the first 32 hex characters of the SHA-256 of your server's full address, such as `https://example.com/mcp`, followed by `.claudemcpcontent.com`. To try an example, add an example server in *Settings > Developer*, *Edit Config*, and restart. In Claude Code, the MCP Apps skills install with `/plugin marketplace add modelcontextprotocol/ext-apps` and `/plugin install mcp-apps@mcp-apps`.

**Claude's display modes.** A page starts inline, in the conversation. It can ask for full screen, and Claude then opens it in a side panel beside the chat, or full screen where there is no side panel. Claude grants the request only after a recent click or key press in the page. Lay the page out again whenever its size changes.

**Claude: full apps.** On November 10, 2026, Claude added full apps. Where a connector supports it, a person can open the tool beside the chat or full screen. They can also open it without a prompt, or pin it to the sidebar. Claude can make changes in the open tool, and the person approves them as for any connector action. It is rolling out on the web and the desktop app, on all plans. Launch partners include Notion, Atlassian's Confluence, Box, Adobe, HubSpot and Canva. Administrators can still restrict a connector's tools as before. For developers, Claude now supports app tools and embedded sites, in public preview.,, These newer parts are not in every organization yet. App tools and embedded sites also need a connector that runs online, not one started on your own computer.

**Claude: a page's own tools.** A page registers its own tools with `app.registerTool()`, which needs version 1.7.0 or later, and gives each tool a schema for its input. Claude does not call the tools of a page whose connector runs on your own computer, so test app tools with the connector online.

**Claude: embedded sites.** A page can frame a website of yours. Claude must allow the site's address for your connector first. For a connector in Claude's directory, its listing must allow that address, and a site that loaded while you tested may still be blocked under a Community listing. Never list a wildcard sandbox address, because then other connectors' pages could frame your site.

**Claude's directory.** In Claude's directory, a connector with screens carries an *Interactive* badge. A connector with screens needs screenshots when you submit it.

**ChatGPT.** ChatGPT implements the MCP Apps standard. A page calls tools with the shared `tools/call`, and ChatGPT keeps `window.openai` for older apps and for its own extras, such as file uploads and its checkout. Check that each extra is there before you use it, so the page still works in other AI apps. On ChatGPT's Business, Enterprise and Edu plans, an administrator adds a custom MCP server and publishes it to the workspace.

**Other AI apps.** As of November 26, 2026, the MCP project lists Claude, Claude Desktop, VS Code GitHub Copilot, Microsoft 365 Copilot, Goose and other AI apps as supporting MCP Apps, and ChatGPT supports them too.,,

**Google: Gemini Enterprise.** Gemini Enterprise shows MCP Apps in a sandboxed frame in the chat, and can open them full screen or in a side panel. An administrator registers the connector as a custom MCP server data store and turns on its tools, which start turned off. Its agents already use A2UI 0.9.1, and Google is moving it to A2UI 1.0.

**Skills over MCP.** On November 24, 2026, Claude put Skills over MCP in public beta, in Claude and in Claude Code. It is on by default on the Pro, Max and Ultra plans. A Team plan gets it once an administrator turns it on, and Enterprise is to follow. As of November 26, 2026, the support matrix also lists VS Code GitHub Copilot and several smaller AI apps, with partial support in ChatGPT, fast-agent and the MCP Inspector.

**Tasks.** Since November 24, 2026, Claude and Claude Code support Tasks on the Pro, Max and Ultra plans, and Team and Enterprise organizations are getting it.

**Sign-in extensions.** On Claude Team and Enterprise, an administrator can authorize a connector once for everyone, if the connector supports it. Through a company's identity provider, Claude supports Okta so far. The official TypeScript and Python code libraries include Client Credentials support, with a client secret or a signed private-key assertion.

**The code libraries.** TypeScript: `@modelcontextprotocol/ext-apps`. Python: `mcp.server.apps`, in the MCP Python code library., The field guide's F0 has the versions.

**Open source.** Goose is listed by the MCP project among the AI apps that show MCP Apps. It is free, and Lab 20's Task 8 can use it as the second AI app. OpenCode shows no screens. It uses the text answer, which is why Lab 20 uses it for the tests.

**What to check before you rely on it:** the MCP project's support table, which lists which AI apps support which extensions, and each AI app's own page for how it asks the person.
