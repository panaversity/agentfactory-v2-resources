# F2. The connector: route A or route B

**Route A, your Chapter 19 staging connector.** The loop calls the connector's `/mcp` address with a test token for Ana at Brightline in an `Authorization: Bearer` header. On staging, Chapter 18 gives one way to get that token: the test person signs in through the staging sign-in server's real pages, as Lab 18's sign-in matrix does, because the test signing key is never deployed (Chapter 18's F8). `npm run token:test -- --person ana --company org_brightline` does just that, with Ana's password from `.secrets/test-users.staging.env` and the connector's address from `.secrets/staging.urls.env`. It writes `CONNECTOR_URL` and `CONNECTOR_TOKEN` into `.secrets/connector.env` and prints only the token's claims. A token lasts 10 minutes, the sign-in server's setting from Chapter 18, so run the command again when the loop gets a 401. If you cannot make a token this way, take route B: everything in this chapter works on it. The loop runs as you, the builder, with that token. Chapter 22 explains why a product must never do this.

**Route A's data.** This lab's `data/` holds Lab 19's rows and three invoices the AP team entered since, INV-8316 to INV-8318, so Brightline has 16 open invoices. Task 0 loads them into staging with `npm run tenant:load -- --company org_brightline --folder data --env staging --replace`, which also embeds the policies again: one small metered call to the embeddings model from Chapter 19. Your dev database keeps Lab 19's 13, which no task in this lab reads. Lab 19's database tests now expect the 16, because the pull-request workflow loads them from these files.

**Route B, the practice connector.** In a second terminal: `npm run connector:practice`. It reads `CONNECTOR_TOKEN` from `.secrets/connector.env` itself, so no one has to copy the token. `PRACTICE_PORT` changes the port, and `PRACTICE_BROKEN=search_policy` (a comma-separated list of tool names) makes those tools always answer "try again", for testing a loop's stops. It listens on `http://127.0.0.1:8760/mcp`, offers the same four tools over MCP (streamable HTTP, MCP's web transport from Chapter 17), reads Brightline's own files, `data/` and `docs/policies/`, the same rows route A loads, and answers 401 to any request without the token. Its policy search weighs shared words, where the real connector searches by meaning, so the passages can come back in another order, with other scores. It has no sign-in server, no companies to keep apart and no database. Stop it with Ctrl+C.

**Listing the tools.** `connectToConnector()` in `src/loop/tools.ts` opens an MCP client session with the token and returns `runTool`, `listTools` and `close`. Task 0's step 5 uses `listTools()`. In Python, the same session's `list_tools()` gives the list.
